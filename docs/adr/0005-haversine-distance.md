# ADR 0005: 距離計算をOSRMからHaversine直線距離に変更

- Status: Accepted
- Date: 2026-04-05
- Supersedes: ADR 0002（ルート計算: OSRM セクション）

## Context

Phase 7（距離ベース検索）の実装にあたり、当初はOSRM（セルフホスト）で車の所要時間を計算する設計だった。
しかしOSRMの運用には以下のコストが判明した：

- 日本地図データ（OSM PBF）のダウンロード・前処理に約5〜6GBのディスクと8GB以上のRAMが必要
- appコンテナとは別のosrmコンテナが常時RAM 2〜4GBを消費
- サブ機サーバーのスペックがこの要件を満たさない可能性がある

## Decision

ルート計算をOSRMではなく **Haversine公式による直線距離** に変更する。

- 自宅座標（設定画面で入力済み）と各釣り場の緯度経度からkm単位の直線距離を計算
- 検索フィルタは「車での所要時間（分）」から「直線距離（km）」に変更
- osrmコンテナをDocker Composeから削除し、appコンテナのみで完結

## 却下した選択肢

- **OSRM継続**: サブ機のRAM・ディスク要件を満たせない可能性があり断念
- **Google Maps Directions API**: 有料（月$200無料枠は超えるリスク）。コスト方針に反する
- **GraphHopper / Valhalla**: OSRMと同様にセルフホストでRAMを要する

## Consequences

- **失われる精度**: 山間部・半島先端など迂回が必要な釣り場では直線距離と実所要時間が大きく乖離する可能性がある
- **得られる利点**: インフラが軽量になり、サブ機への依存が下がる。実装もシンプル
- **UI変更**: 検索フィルタのラベルを「所要時間」→「直線距離（km）」に変更
- **将来の拡張**: サブ機スペックが向上した場合、OSRMへの切り替えは検索ロジック部分のみ差し替えで対応可能
