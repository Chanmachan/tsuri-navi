# idea: tsuri-navi アイデアdump

## ユーザー像
- 福島県いわき市在住の釣り人
- 海釣り中心
- 釣り方: サビキ、投げ釣り、ルアー、エギング
- ショアジギングで青物を釣りたい（まだ釣果なし）
- 割となんでも釣る

## ホームポイント
- 久ノ浜漁港（いわき市）— よく行く
    - 2026/3/14 に行ったが若潮＋海荒れ＋港内濁りで当たりゼロ→すぐ帰った
- 桃浦漁港（宮城県石巻市）— 2026/1/24に行って釣れなかった。リベンジしたい
- 四国方面 — 旅行がてら良い場所があれば行きたい。おすすめをアプリ側でピックアップしてほしい

## 一番解決したい課題
- **行ってみたら「今日ダメじゃん」を避けたい**
- タイドグラフBIは情報はあるが「結局いつ行けばいいの？」が分かりづらい
- 行く前に「この日のこの時間帯が良い」と判断できることが最重要

## 欲しい機能（優先度順）
1. 天気・風・波の情報
2. 潮汐グラフ（タイドグラフ）— 今日/明日
3. 釣り場を選ぶ（複数ポイント登録）
4. 今の時期に狙える魚と釣り方・餌の提案
5. **釣りやすさスコア**（点数化）— 潮・天気・風・波・時期を総合判断
6. **時間帯ごとのおすすめ** — 何時に行くべきか
7. 週間カレンダー — 良い日が一目で分かる
8. プッシュ通知 — 「今週末、久ノ浜が好条件です」的な

## 釣り場について
- 公式の釣り場（漁港・堤防）だけでなく、ちょっとした岩礁なども含めたい
- 地図上で自由にポイントを追加できると良さそう
- 四国のおすすめスポットはアプリ側でいくつかプリセット

## 距離ベースのおすすめ検索
- 自宅（いわき市）からの距離を指定して、その範囲内の釣り場を検索したい
- 行く日を指定 → その日の条件が良い場所を距離順・スコア順で表示
- 例: 「来週土曜、片道2時間以内で一番釣れそうな場所は？」に答える
- 登録済みポイントだけでなく、DB内の釣り場全体から探せると理想
- **距離・時間は可変**（UIで自由に変更可能にする）
- **車での所要時間で計算**（Google Maps Directions API等）
- 遠征もするので、短距離（30分）〜長距離（5時間+）まで幅広く対応
- 近場のちょい釣りも、四国遠征もカバーできるUI

## UI/UXの方向性
- ぱっと見で分かりやすい
- データ重視より「結論ファースト」
    - 今日行くべきか？ → ○/△/× がすぐ分かる
    - 何時がベスト？ → 時間帯ハイライト
- タイドグラフBIの不満: 情報はあるが判断が難しい

## 技術方針（仮）
- PWA（Progressive Web App）で作る
    - Webだがホーム画面追加でアプリっぽく使える
    - App Store審査不要
    - プッシュ通知もPWAで対応可能
- **or Swift（ネイティブiOS）** — 要検討
    - SwiftでもAPIリクエストは普通に可能（URLSession等）
    - ネイティブならプッシュ通知が確実、UXも良い
    - ただしApp Store公開しない前提 → TestFlight or サイドロード
- **サブ機をサーバーとして使える**
    - バックエンドAPI、定期バッチ（天気データ取得・スコア計算）に活用可能
    - プッシュ通知の送信サーバーにもなる
- **AIエージェント組み込みOK**
    - 魚種提案、釣り場おすすめをLLMで動的生成
    - Claude APIをバックエンドから呼ぶ構成

## API候補
### 潮汐
- tide736.net — 日本沿岸736港、無料、サポートなし
- Storm Glass — 無料枠10req/日、天気+潮汐ワンストップ
- WorldTides — 世界対応、クレジット制
- TideCheck — 日本705地点、無料50req/日

### 天気
- Open-Meteo — 完全無料・オープンソース
- OpenWeatherMap — 定番
- Storm Glass — 潮汐と一緒に取れる

### 魚種×季節×餌
- 公開APIなし
- 自前DBで持つ or Claude APIで動的生成
